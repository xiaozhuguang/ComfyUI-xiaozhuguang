# 小珠光视频姿势编辑器

面向视频骨骼序列的 ComfyUI 插件。使用已有 SDPOSE 提取骨骼，再在独立大窗口中批量调整、播放和逐帧检查。无需 npm 构建，也不需要另起编辑器服务器。

## 安装

本功能已合并进 `ComfyUI-xiaozhuguang`。重启 ComfyUI 并强制刷新浏览器后即可使用。

插件使用 ComfyUI 官方的节点 UI 返回、前端扩展和 HTTP 路由机制：
https://docs.comfy.org/development/comfyui-server/comms_messages

`examples/sdpose-video-editor.json` 基于你的原工作流生成，保留 SDPOSE 与小珠光视频加载/保存节点，把中间调整替换成本插件。导入后重新选择本机视频。该示例仍需要你的 ComfyUI-xiaozhuguang 视频节点，插件本身不依赖它或 BodyRatioMapper。

## 连接与使用

1. 视频加载节点输出 IMAGE，连接现有的 `SDPoseKeypointExtractor`。
2. SDPOSE 的 POSE_KEYPOINT 连接 `小珠光视频姿势编辑器` 的 `pose_keypoint`。
3. 可选：把同一视频加载节点的 IMAGE 同时连接编辑器 `images`，用于原视频帧叠加预览。填写加载后的实际帧率，默认 25。
4. 首次执行一次工作流，让编辑节点加载序列；未修改时输出原始骨骼。
5. 点击节点的“打开视频骨骼编辑器”。播放或拖动时间轴检查整段骨骼。
6. 在时间线上定位到要调整的帧，然后拖动身体关节、整体平移或调整比例；松开鼠标/滑块后会自动在该帧创建关键帧。时间线上的菱形标记可点击跳转，关键帧列表可删除单项。
7. 点击“保存到节点”，然后再次执行工作流，输出调整后的整段骨骼。
8. 姿势编辑器的 `pose_keypoint` 输出可直接连接 ComfyUI 自带或你已安装的姿势渲染节点，再连接视频保存节点。

修改保存于 `edits_json` 节点参数，随 ComfyUI 工作流保存。后端按原始输入重新应用操作，不累计重复缩放。输出不依赖临时预览缓存，因此 API 工作流和迁移后的项目可重放相同调整。

## 关键帧行为

- 连续调整（身体比例、关节拖动和整体平移）按当前帧保存关键帧，相邻关键帧之间线性过渡；首尾之外保持最近关键帧的值。只有一个关键帧时，该调整应用于整段视频。
- 手掌修复始终开启，会逐帧固定交换 SDPOSE 中反置的左右手掌字段，并先于手动调整应用；不创建关键帧。
- 切换“姿势调节”显示比例滑条，切换“姿势补全”在右侧编号骨架图中选择关节，在工作区移动鼠标预览，按住拖动绘制，松开后保存；放置后可继续补画其他关节。完成后可在多个帧设置同一关节位置，相邻位置会插值，单个位置会保持到整段。补画与其他编辑一样随工作流保存，置信度为 0.8。
- 人物按每帧 people 数组的索引选择，并未做跨帧身份追踪。SDPOSE 上游若只有单人输出，编辑器不会额外检测人物。
- 比例调整包括头部宽高、脖长、肩宽、胯宽、上下臂长、躯干、上下腿长、手掌和脚部大小。
- 拖动身体关节以归一化位移形成关键帧修正，过渡时保留每帧原来的动作差异；拖动关节时会自动选中该人物。拖动脖子点或头颈连接点时，头部关节和脸部关键点会随头部一起移动，并可继续叠加脖子长度比例调整。
- 平移和比例可以作用于全部人物或指定人物；脸、手、脚随骨骼相应部分移动，置信度和未知字段保留。
- 线宽用于即时屏幕预览。最终渲染使用渲染节点的 stick_width；编辑参数不修改渲染节点设置。
- 可使用节点 images 预览帧，或在浏览器加载本地参考视频。参考视频不上传到服务器，需与骨骼的帧率、裁剪尺寸、起始帧一致。

## 数据与迁移

输入输出保持 SDPOSE 的 OpenPose 帧数组：canvas_width、canvas_height、people；身体采用 18 点，保留脸、手、脚字段。并不转换为只有 17 点的标注格式。

```
_xzg_pose/
  pose_core.py          # 无 ComfyUI/torch 依赖的纯 Python 编辑核心
  nodes.py              # ComfyUI 节点适配
  routes.py             # 编辑预览的 HTTP 适配
  session_store.py      # 有界预览缓存
  web/editor/pose-core.js # 无框架依赖的浏览器编辑核心
  web/editor/           # 可移植编辑界面
  web/extension.js      # 编辑器窗口适配（主入口在插件 web/）
  examples/            # 参考工作流
  tests/               # 处理核心与前后端一致性测试
```

迁移至其他项目时，可以直接复用 pose_core.py 的 `apply_edits(frames, edits)` 和前端 pose-core.js 的 `applySequence(frames, operations)`。关键帧编辑操作不依赖 ComfyUI。

```json
{"version":1,"operations":[
  {"type":"scale","frame":0,"person":-1,"values":{"shoulders":1.2,"hips":0.9}},
  {"type":"joint","frame":24,"person":0,"joint":4,"dx":0.02,"dy":-0.01}
]}
```

编辑节点保存的 source_digest 校验源骨骼，防止把旧视频调整误用到新输入。源数据变化时，点击节点的“清除调整并重新加载”，执行后重新编辑；清除调整按钮会清空编辑操作并恢复节点默认的左右手修正行为。

预览缓存最多保留最近 4 个编辑会话；重启或失效后重新执行节点即可，已保存的编辑参数不丢失。工作流文件本身仍需主动保存。

## 当前边界

首版支持身体关节拖动，脸、手、脚可预览并随身体调整，但尚未提供每个面部/手指关键点的独立拖动、IK、旋转或自动身份追踪。比例变换是本插件自己的二维算法，不保证逐像素复现 BodyRatioMapper 的内部实现。

编辑不会阻塞执行队列等待交互，流程为“执行加载 → 编辑保存 → 重新执行”。首次加载时，下游会得到原始骨骼；如不希望提前保存视频，可先只连接编辑器，编辑完成后再连接渲染/视频保存。

## 检查

在插件目录运行 `python -m unittest discover -s tests`。运行 `node tests/parity.mjs tests/parity-fixture.json` 检查浏览器预览与 Python 输出的数值一致性。浏览器端文件均为原生 ES modules，无构建步骤。

## 左右手修正

左右按人物自身定义，而非屏幕左右。“自动匹配手掌与手腕”逐帧比较左右手掌根部和身体腕关节的置信度加权距离；仅在关节点有效且交换明显改善匹配时交换两组手部数据，不改手臂。遮挡、低置信度或左右距离接近时可能无法判断；编辑器会提示当前帧没有触发自动交换，此时可用“交换左右手掌”手动修正。操作会成为关键帧并可撤销，随节点参数保存。

姿势补全中右键骨架图编号可隐藏对应关节及相连骨骼，也可撤销或重新绘制。删除状态随工作流保存；单个关键帧作用于全片，多个关键帧之间保持前一个关键帧的删除状态。此功能更新后需重启后端并强刷页面。

点击补全示意图中的缺失编号，会根据已有相邻关节和示意图方向先补出初始关节，再拖动调整。初始位置仅作为手动调整的起点，可撤销，随关键帧保存。

编辑器顶部的饱和度滑条调节骨架预览颜色（0 为灰度、1 为原色、最高 3）。仅保存在当前编辑器内存中，重新打开恢复默认，不写入工作流或改变节点输出。更新后强刷页面即可，无需重启后端。


本功能由主插件注册节点与路由。浏览器扩展入口位于主插件 `extension.json` 中声明的 `web/xzg_pose_editor.js`，编辑器页面从 `/extensions/xiaozhuguang/web/editor/` 提供。
